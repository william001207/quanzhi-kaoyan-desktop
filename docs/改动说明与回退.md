## 改动清单

### 1. 单实例锁　`electron/main.js`

**改了什么**：只允许运行一个应用实例。重复点图标会把已有窗口拉到前面。

**为什么**：双击两次图标会启动两个实例，两个实例同时打开同一个数据库文件夹，PostgreSQL 的并发控制在 WASM 单进程里是失效的——这是**真实的数据损坏路径**，也是"应用打不开"的常见原因之一（第二个实例抢不到端口就崩了）。

**对你使用的影响**：正常使用无感知。唯一的区别是：重复点图标不会再开出第二个窗口。

**风险**：低。

**怎么退回**：删掉 `electron/main.js` 中 `if (!app.requestSingleInstanceLock()) {` 那一段，恢复成原来的 `app.whenReady().then(...)`。

---

### 2. 启动失败弹窗　`electron/main.js`

**改了什么**：启动失败时弹窗说明原因，而不是静默退出。

**为什么**：原来服务端起不来时，`console.error` 打在终端里——打包后的应用用户根本看不到。表现就是"双击图标 → 加载页闪一下 → 应用消失"，你之前遇到的很可能就是这种情况，但完全无从排查。

现在会明确告诉你：是找不到服务端程序、数据库损坏、还是端口被占用。

**对你使用的影响**：只有出问题时才会出现弹窗。正常启动完全不变。

**风险**：低。

**怎么退回**：把 `dialog.showErrorBox(...)` 那两处删掉即可。

---

### 3. 退出前等待数据写完　`electron/main.js` + `server/main.ts` + `server/database/local-db.ts`

**改了什么**：
- 关窗时先给服务端发"正常关闭"信号，最多等 2.5 秒
- 服务端收到信号后，先关 HTTP 服务，再关数据库（`closeDb()`）
- 2 秒还没退出就强制结束，不会卡住

**为什么**：PGlite 是跑在 WASM 里的真 PostgreSQL，有自己的内存缓冲和 WAL 日志。原来关窗是直接杀进程——**不保证数据已经写到磁盘**。你刚标完 20 道错题就关窗口，有概率丢掉最后几次写入。

这是本次改动里对你**实际收益最大**的一处。

**对你使用的影响**：关窗后应用可能在程序坞里多停留一两秒才完全退出。这是唯一可感知的变化。

**风险**：中低。如果这段逻辑出问题，表现是"关窗后应用不退出"。

**如果关不掉怎么办**：打开「活动监视器」搜索"全职高手考研系统"强制退出；或终端执行：

```bash
killall "全职高手考研系统" 2>/dev/null || pkill -f quanzhi-kaoyan
```

**怎么退回**：删掉 `electron/main.js` 里 `app.on('before-quit', (event) => {...})` 整段，恢复成原来的一行 `app.on('before-quit', () => stopServer());`。服务端侧的 `shutdown()` 留着也无害。

---

### 4. CORS 收紧　`server/platform/index.ts`

**改了什么**：跨域请求只允许本机回环来源。原来是 `origin: true`，等于**放行任何来源**。
（早期版本把来源写死成 `http://127.0.0.1:17890`；端口改为随机分配后，改成了「校验来源是不是 `127.0.0.1` / `localhost` / `[::1]`，端口不限」。）

**为什么**：`origin: true` 会把请求方来源原样反射回去，配合 `credentials: true`，意味着你开着应用时随便打开一个恶意网页，那个网页就能跨域读取甚至改写你的错题本和复习记录。CSRF 令牌是硬编码常量（`desktop-local-csrf-token`），等于没有防护。

**对你使用的影响**：**零影响**。应用页面本身就是从本机服务加载的，和 API 同源。同源请求根本不走 CORS 检查，改不改都能用。

**风险**：低。**万一**出现"页面能打开但数据加载不出来"，这是第一个要退回的地方。

**怎么退回**：把 `origin: [...]` 改回 `origin: true`。

---

### 5. 窗口跳转拦截　`electron/main.js`

**改了什么**：应用窗口内如果要跳到外部网址，改为用系统浏览器打开。

**为什么**：原来只拦了 `window.open`（新窗口），没拦同一窗口内的跳转。

**对你使用的影响**：几乎无。页面内部的导航（React 路由）走的是 `history.pushState`，不触发这个拦截。只有真的发生整页跳转到外网时才会被接管。

**风险**：低。如果出现"点某个按钮页面没反应"，可以退回这里。

**怎么退回**：删掉 `mainWindow.webContents.on('will-navigate', ...)` 那一段。

---

### 6. 构建流程改造　`.github/workflows/build.yml`、`scripts/`

**改了什么**：
- 两条重复的工作流合并成一个
- 删掉构建时的三个下载脚本（源码 / 前端资源 / 图标）
- 新增构建前完整性自检
- 产物文件名统一带版本号，不再靠脚本重命名

**对你使用的影响**：**不涉及运行时**，只影响"能不能打包成功"。这正是你之前反复失败的部分。

**风险**：如果你本地文件不齐，`verify_repo.py` 会直接拦下并告诉你缺什么——这是设计如此，不是故障。
