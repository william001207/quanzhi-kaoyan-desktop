# Release 正文（GitHub 发布页用）

每个版本要贴进 GitHub Release 页面的文字，都存在这里。

**怎么用**：发布时，找到对应版本那一节，**从 `## 更新内容` 开始、复制到该节最后一行**，粘贴进 Release 的描述框即可。不要带上 `## v1.1.3` 这层标题，也不要带上其它版本的内容。

**模板约定**（每次写新版正文照这个来）：

```
## 更新内容
### 新功能
- xxx
### 界面修复
- xxx修复（补充做法或范围）
### 数据治理（首次启动自动同步）
- xxx
- 题库规模：xxx 道真题 / xxx 个知识点
```

- 章节只用这三类：`新功能` / `界面修复` / `数据治理（首次启动自动同步）`
- 不带版本号标题、不带日期、不带 Compare 链接
- 界面类条目习惯把「修复」放在句尾，例如「大纲页章节名截断修复（侧栏加宽，图标悬浮不占位）」
- 题库规模放在「数据治理」小节最后一条
- 每条一行写完，不写 `DATA_VERSION` 具体值、`client-src` 构建路径这类工程细节
- 某个版本没有对应内容时，那一节直接不写，不要凑

> 这份是**给人读的发布说明**；`CHANGELOG.md` 是**仓库档案**，两套格式不一样，别互相覆盖。
