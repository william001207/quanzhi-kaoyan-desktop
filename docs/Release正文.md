# Release 正文（GitHub 发布页用）

每个版本要贴进 GitHub Release 页面的文字，都存在这里。

**怎么用**：发布时，找到对应版本那一节，**从 `## 更新内容` 开始、复制到该节最后一行**，粘贴进 Release 的描述框即可。不要带上 `## v1.1.4` 这层标题，也不要带上其它版本的内容。

> AI 在对话里交付正文时会给**纯文本**（不包代码框），直接复制即可；
> 本文件里的代码框只是模板样例，不是交付物。

**模板约定**（每次写新版正文照这个来，**章节之间不留空行**）：

```
## 更新内容
### 新功能
- xxx
### 界面修复
- xxx修复（补充做法或范围）
### 数据治理（首次启动自动同步）
- xxx
- 题库规模：xxx 道真题 / xxx 个知识点
```

- 章节只用这三类：`新功能` / `界面修复` / `数据治理（首次启动自动同步）`
- **条目之间、章节之间都不空行**（与 v1.1.1 保持一致）
- 每条一行写完，界面类条目把「修复」放在句尾
- 题库规模放在「数据治理」小节最后一条
- 不带版本号标题、不带日期、不带链接，不写 `DATA_VERSION` 具体值、`client-src` 构建路径这类工程细节
- 某个版本没有对应内容时，那一节直接不写，不要凑

> 这份是**给人读的发布说明**；`CHANGELOG.md` 是**仓库档案**，两套格式不一样，别互相覆盖。

## v1.1.7

## 更新内容
### 修复
- 启动时清理残留进程的报错修复（旧进程恰好自己退出时会抛出「Cannot access 'timer' before initialization」，自动恢复流程直接中断、应用卡在加载页）
- 「残留进程最多自动重试一次」真正生效修复（原逻辑每轮都把重试标记清零，极端情况下可能反复重启）
- 本地服务端口号读取不完整修复（管道把就绪消息拆成两段时，可能读错端口或永远等不到就绪；改为按整行解析）
- 结束残留进程前先核实身份修复（原先只凭进程编号就动手，编号被系统回收后可能结束掉无关程序；现在确认是本应用的服务才结束，否则改为接管记录）
- 单实例保护加强（实例标记改为原子创建；修正两个进程同时接管过期记录时会把对方刚建好的标记删掉的竞争，不会再出现两个服务同开同一个数据库）
- 启动失败时不再留下没有窗口的空进程
### 数据治理（首次启动自动同步）
- 本次无数据变动，不触发同步
- 题库规模：1705 道真题 / 1117 个知识点 / 8 个科目
